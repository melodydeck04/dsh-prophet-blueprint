# 规格：审核助手长对话滚动

状态：已实现

## 问题

Spec 助手使用有高度边界的纵向 flex 对话区，但消息轮次和活动卡仍是可以收缩的 flex 子项。历史内容变长后，浏览器可能为了满足面板高度而压缩较早的条目，而不是保留可读高度并让对话区滚动。很长的单条消息也没有明确的内部溢出边界；流式输出期间无条件自动滚到底部，还会把正在阅读旧内容的开发者拉回最新消息。

## 决策

在桌面布局中让审核面板具有确定高度，在上下堆叠布局中也保留有界高度。禁止对话条目收缩，把每条消息和活动区域限制在当前栏宽以内，并为超长消息正文和活动详情提供独立的纵向、横向溢出处理。普通文字继续安全换行，代码和连续长字符可以滚动，但不能把审核栏撑宽。

记录开发者是否处于对话底部附近。只有视图仍贴近底部时才跟随流式输出；开发者向上滚动后保留当前阅读位置，并提供明确按钮返回最新内容。

版本升级为 `0.13.1`，让 Host、浏览器客户端和包版本能够明确显示是否已加载修复后的样式。

## 其他方案

**取消面板高度限制。** 不采用，因为长审核对话会让整个 Blueprint 页面无限增长，输入区和文档对照区域也失去稳定位置。

**始终强制跳到最新消息。** 不采用，因为助手仍在流式输出时，开发者将无法阅读之前的轮次。

**截断长消息。** 不采用，因为审核细节和生成的规格必须保持完整；有界滚动优于丢失内容。

## 后果

较长的审核历史现在会保留消息轮次和活动卡的可读高度，由对话视口统一滚动。超长消息正文、活动详情、代码块和表格会完整保留在有边界的内部滚动区中，且不能撑宽审核栏。停留底部时仍会自然跟随流式输出；手动向上滚动后会保留当前阅读位置，直到选择**回到最新**。为了在稳定的 Spec 工作区中保留完整长内容，嵌套滚动是明确接受的取舍。

# Blueprint Spec 工作区

[English](web-dashboard.md) | 中文

## 实现什么

Blueprint 工作区会在任何 AI 规划开始前，为每个功能建立一份由开发者确认的身份。开发者填写显示名称、选择上级功能并确认稳定的本地键；Host 据此生成规范功能 ID，以及所有功能说明、Spec 和审批路径。AI 只负责生成文档内容，不负责选择、搜索或关联文件名。

## 最终效果

新的顶层功能直接使用已确认的本地键作为 ID；子功能使用 `<parent-id>--<local-key>`，同时在扁平功能目录中继续通过明确的 `Parent` 元数据表达层级。Host 会准备并返回一份工件映射，其中包含精确的功能定义、中英文功能说明、中英文 proposed Spec 和审批位置。dashboard 直接读取这份映射，因此游离文件或相似文件名不会成为当前功能。现有旧 ID 继续可读，只能通过明确的迁移预览进行规范化。

## 怎么使用

创建功能时填写名称、选择上级，并确认建议的本地键；非 ASCII 名称必须由开发者提供本地键，不能让 AI 翻译生成。检查得到的 ID 和全部工件路径后，再生成开发方案。Blueprint 会先准备中英文配对文件，再提示助手填写；只有这些已登记文件有效时，方案才算完成。旧的纯数字或误导性 ID 需要修改时，使用迁移操作并在确认前检查每一个受影响路径。

## 注意事项

工件准备完成后，功能 ID 保持不可变；修改显示名称不会重命名文件，重新挂接上级必须使用同一套显式迁移流程。新功能拒绝纯数字 ID。迁移会检查冲突，以可恢复方式更新后代身份、Feature 和 Spec 引用，并使旧审批失效，不会把审批直接带到新身份。英文生命周期 Spec 仍是机器解析的结构主文件，双语内容仍需审阅，功能实现必须由开发者批准当前精确 Spec 配对后才能开始。首选 Blueprint Web；如果 Web 无法打开，开发者可以明确运行 `design-blueprint approve <feature-id> --spec-hash <sha256> --yes`，它会执行相同的精确哈希校验和原子审批写入。
